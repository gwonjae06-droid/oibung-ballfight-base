# 오이붕 아레나 코드 구조 점검 (2026-11-02)

## 범위와 판정
- 점검 대상: `main` 기준 111개 JS / 28개 CSS가 있는 저장소의 구조, HTML 로더, 콤보·전투·탑·PvP의 핵심 경로, 기존 회귀 테스트.
- 이번 점검은 정적 코드 감사 및 GitHub Actions 회귀 테스트 기반이다. 111개 JavaScript 파일 전체를 모두 수동으로 한 줄씩 감사했거나 실제 브라우저에서 모든 보스를 플레이한 것은 아니다.
- **결론: 기능 단위의 파일 분리는 상당히 진행되었지만, 전역 상태·로드 순서·대형 파일·누적 CSS 덮어쓰기 때문에 유지보수 위험이 중상 수준이다. 단일 거대 파일의 전형적인 스파게티 코드는 아니지만, 모듈 결합이 강한 편이다.**
- 대규모 분리/이름 변경을 즉시 수행하면 기존 저장 데이터 및 탑·기세·PvP 결합 지점을 망가뜨릴 수 있으므로, 이번 커밋에서는 전장 콤보 이펙트를 독립 모듈로 추가하고 기존 판정에는 작고 명확한 후크만 연결했다.

## 확인한 강점
1. 전투 판정과 외관을 분리하는 파일이 이미 다수 존재한다(물리, 기세, 스킬, 탑, 보스 FX).
2. `index.html`의 105개 스크립트 경로에 중복된 로딩 항목은 확인되지 않았다.
3. 기존 자동 회귀 테스트가 물리·이펙트·타워 진행·기세 등을 폭넓게 검증하며 GitHub Actions에 문법 검사 단계가 있다.
4. 보스용 임시 캐릭터와 저장된 커스텀 캐릭터를 분리하는 코드가 있다(`tower-challenge.js`).

## 위험 및 개선 권고 (우선순위 순)

### 높음 — 암묵적인 전역 상태와 수동 로드 순서
- `js/core/state.js`가 `players`, `CHARACTER_DEFS`, `CUSTOM_DEFS`, `BEHAVIORS`, 전투 상태를 전역 변수로 제공한다.
- `js/core/engine.js` 522줄에서 `globalThis.` 사용이 약 100곳, `js/features/skill-forge.js` 1,109줄에서 `globalThis`/`global` 참조가 약 167곳이다(문자열 패턴 카운트로 정밀한 의미 분석은 아님).
- `index.html`은 105개의 `<script src>`를 로드한다. 컴파일 시점의 의존성 검사가 없어서 스크립트 순서 변경/누락이 런타임 오류로 이어질 수 있다.
- **권고**: 게임 실행 상태를 읽기 전용 접근자와 명시적 의존성 맵으로 감싸고, 한 기능씩 ES 모듈 또는 등록 기반 인터페이스로 이관. HTML 순서 및 필수 전역 객체를 CI에서 검사.

### 높음 — 전투·스킬 핵심 파일의 단일 책임 초과
- `js/features/skill-forge.js` 약 1,109줄은 스킬 정규화, 등록, 충돌/피해 판정, 자동 발동 등 서로 다른 책임이 섞여 있다.
- `js/features/advanced-combat.js` 약 1,021줄, `js/features/tower-challenge.js` 약 735줄도 크다.
- **권고**: 먼저 `SkillForge.hit`와 상태이상·회복·피해 적용을 테스트로 고정한 후 데이터 정의/전투 판정/런타임 스케줄러를 순차적으로 분리. 지금 대규모 재작성은 금지.

### 중간 — 도전의 탑 UI와 전투 흐름의 강한 결합
- `tower-challenge.js` 하나가 UI 생성(`innerHTML`), 캐릭터 목록, 저장 기록, 층 진행, 적 등록/삭제, 전투 엔진 연결을 관리한다.
- **권고**: `TowerRunState`(상태/층 전이), `TowerFighterPicker`(화면/입력), `TowerEncounterFactory`(일회성 적)로 분리하되 기존 `ArenaTower` API는 유지.

### 중간 — CSS 누적 덮어쓰기와 시각적 회귀
- `css/style.css` 약 2,214줄에 `.canvas-wrapper`가 여러 구역(예: 113, 567, 1243줄 부근)에서 재선언된다. 다른 CSS 파일에서도 화면별로 같은 선택자가 보강된다.
- 단순한 중복이 모두 오류는 아니지만, 우선순위 규칙과 파일 로딩 순서에 의존하기 때문에 레이아웃 수정 시 예상치 못한 화면이 바뀔 수 있다.
- **권고**: 로비/전장/타워/스튜디오를 CSS 레이어 또는 이름공간으로 구분하고, 시각적 스냅샷(PC·모바일)을 추가.

### 중간 — 로컬 전투와 온라인 전투의 개별 로더
- `index.html`의 105개 스크립트와 `pvp-runtime.html`의 37개 스크립트가 별도로 관리된다. 서로 다른 런타임은 의도된 설계지만 공용 모듈의 `?v=` 캐시 버전이 어긋날 수 있다.
- **이번 수정**: `js/core/engine.js`의 캐시 버전을 두 진입점에 맞췄다.
- **권고**: 버전 매니페스트 하나에서 공통 스크립트 태그를 생성하고, CI에서 두 진입점의 공통 모듈 버전을 비교.

### 중간 — 브라우저 시각/성능 테스트의 공백
- 테스트는 물리·상태전이를 폭넓게 보지만 실제 Canvas 시각 순서, 모바일 터치, 애니메이션 프레임 속도와 포커스 배치는 완전 검증하지 못한다.
- **권고**: Playwright로 기본/커스텀 캐릭터 선택→1층 시작→층 클리어→다음층, 고대의 존재 준비 화면, 3/5/8/12/20 콤보 스크린샷, 390px·1366px 뷰포트 시나리오를 자동화.

### 낮음 — 은퇴한 기능의 호환 코드
- `js/core/state.js`와 `js/core/engine.js`에는 오래된 경제/베팅 상태가 호환성을 위해 남아 있다.
- 현재 UI에서 사용하지 않는 기능이라도 저장 파일 호환성과 테스트를 먼저 확인한 후 정리할 것. 삭제를 서두르지 말 것.

## 이번 커밋에서 실제 반영한 안전한 구조 개선
- `js/features/combo-screen-fx.js`와 `css/combo-screen-fx.css`에 전장 이펙트를 독립화.
- 기존 `ArenaCombatV2.signal`은 **인정된 내 캐릭터 충돌**만 FX에 통지. HP/스킬/넉백/기세 판정 미변경.
- 효과 레이어는 전장당 한 개만 생성하며 CSS 애니메이션 중심; DOM 요소를 매 프레임 생성하지 않는다.
- 전투 정지·종료·콤보 종료 시 FX 상태를 초기화하고, 모바일/움직임 감소/포인터 비차단 옵션 제공.
- `tests/combo-screen-fx.test.cjs`에서 콤보 단계, 적 캐릭터 제외, 중복 레이어 없음, 리셋, 시각 접근성을 검증.

## 추천 리팩터링 순서
1. 현행 버전에서 E2E 및 시각 회귀 테스트 확보.
2. 공통 스크립트의 로드 순서·버전 매니페스트 통일.
3. `SkillForge` 피해/상태이상 로직부터 독립 모듈 분리.
4. 탑 상태 머신과 준비 UI 분리(외부 API는 유지).
5. CSS 이름공간/레이어 정리.
6. 그 뒤에야 전역 `state.js`를 점진적으로 캡슐화.

**안전 조건**: 저장된 캐릭터 데이터 형식, 기세 100 스킬 사용 규칙, 기존 PvP 판정, 탑 진행/보스 HP를 동일하게 유지할 것.
